## Polly Integration (Inside ClientB Handler)

```csharp
public class OrderPlacedHandler : IHandleMessages<OrderPlaced>
{
    private readonly PollyPolicies _pollyPolicies;

    public async Task Handle(OrderPlaced message, IMessageHandlerContext context)
    {
        // Polly logic is HERE - inside the handler, not in HTTP layer
        
        if (message.ExceptionType == "retry")
        {
            // ?? Retry Policy (configured in appsettings.json)
            await _pollyPolicies.RetryPipeline.ExecuteAsync(
                async token => await ProcessWithRetry(message));
        }
        else if (message.ExceptionType == "circuit-breaker")
        {
            // ? Circuit Breaker Policy (configured in appsettings.json)
            await _pollyPolicies.CircuitBreakerPipeline.ExecuteAsync(
                async token => await ProcessWithCircuitBreaker(message));
        }
        else
        {
            // ? Normal processing
            await ProcessNormally(message);
        }
    }
}
```

## Why This is Choreography

? **Decentralized Control**: Each service decides how to react to events
? **No Direct Knowledge**: SenderApp doesn't know ClientA or ClientB exist
? **Event-Based**: Communication via events, not commands
? **Independent Scaling**: Add ClientC without touching SenderApp
? **Loose Coupling**: Change ClientB without affecting ClientA or SenderApp
